## X1. なぜ関門が必要か

G1 判定は 160セル・約70.7時間（fp32、6.912M forward × 36.2 ms 実測）を要する。
**効果量が測定の分解能を下回っていれば、70.7時間を投じても順位は数値誤差で決まる。**
実行前に分解能を確認し、満たさなければ実行しないことを登録する。

## X2. 分解能の基準値 1.183e-3 bits の出所

`03_解析/plan_b/G1_judgement/batch_equivalence_20260927.json`（2026-09-27）。
**バッチサイズのみを変えた（batch=1 対 batch=N）ときの JS の絶対差の最大値**が 1.183e-3 bits だった。

**これは実行間のばらつきではない。** batch=1 の反復は bit-identical（`g1_audit_ab.py` 監査A、
max|run1−run2| = 0）である。1.183e-3 は**「数値的に等価な実装を選び直すと値がどれだけ動くか」**であり、
**別の実装で再現するかどうかの尺度**として用いる。

## X3. 関門（実行前に固定。結果を見て変更しない）

**layer 11 の2方向（`get_candidate_dirs` の `ica[0]` と `jac[0]`）× 2アーム = 4セル**について、
**登録済みの PMF 床（`g1.pmf_draws`, §5）100本**で以下を測る。

### 関門1：効果量 対 実装差
各セルについて `n_within = #{ k : |JS(床_k) − JS(軸)| < 1.183e-3 }` を数える。

- **`n_within` ≥ 50 のセル** → **そのセルは判定不能**とする。該当アームの160セル実行は行わない
- **`n_within` < 50** → そのアームは分解能を満たす

### 関門2：精度をまたいだ順位の安定性
同一の軸・同一の床10本について fp16 と fp32 で測り、
`swaps = #{ k : (JS(床_k) > JS(軸)) が fp16 と fp32 で異なる }` を数える。

- **swaps = 0** → 順位は実装に依存しない
- **swaps 1〜2** → グレー。**実行してよいが、原稿に順位の不安定性を明記する**
- **swaps ≥ 3** → **結論が実装依存。そのアームは実行しない**

### 実行する場合の精度
**fp32 で実行する。** fp32 は 36.2 ms/pass で fp16 と実質同コスト（fp16 の実効 35 ms）であり、
**速度を犠牲にせず実装依存性を1つ減らせるため、fp16 を選ぶ理由がない。**
fp32 も反復は bit-identical であることを確認済み（v2 probe, max_abs = 0）。

## X4. 関門を満たさなかったアームの報告方法

**「測らなかった」ではなく「測定器の分解能を下回った」と書く。**
本追記の `n_within` と `swaps` の実測値を併記し、**そのアームについて肯定も否定も主張しない。**
**分解能不足を理由に、都合の良いアームだけを残すことはしない**（両アームに同じ関門を当てる）。
