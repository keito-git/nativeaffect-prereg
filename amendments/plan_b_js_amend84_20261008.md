## CC1. 実装欠陥 第10件：Phi-3 の読み出しは全クラスが同一トークンだった

追記82 で `no-emotion` の割り当てを直し、クラス間でトークン ID が重複したら
異常終了させる検査を入れた。その検査が Phi-3-medium で発火した。

```
読み出しが空のクラス: anger
```

原因を測定した。各モデルで13クラスの単語の**先頭トークン ID の異なり数**を数えた。

| モデル | 異なり数 | `" anger"` の分解 |
|---|---|---|
| **Phi-3-medium-4k-instruct** | **1/13** | `[29871, 27343]` = `['', 'anger']` |
| Llama-3.2-1B-Instruct | 13/13 | `[19788]` = `[' anger']` |
| gemma-2-2b-it | 13/13 | `[23790]` = `[' anger']` |
| Mistral-Nemo-Instruct-2407 | 13/13 | `[26202]` = `[' anger']` |

**Phi-3 の SentencePiece トークナイザは語の前に裸の語境界片（id 29871・復号すると空文字列）を
出す。** 旧コードは `cc[0]` を取っていたため、**13クラス全ての読み出し座標が同一トークン**に
なっていた。13座標が同一なら差分ベクトルは定数であり、中心化（$I - \mathbf{1}\mathbf{1}^\top/13$）で
**ゼロになる**。観測された署名（$|S| \approx 7\times10^{-4}$・全族 0/13・標準化超過 $\pm 0.00$）は
これである。

### 撤回する記述

- 追記80・81 の「Phi-3-medium は縮退・判定から除外」
- 追記81 の「Phi 系列2モデルが同じ署名で落ちている点は限界としてそのまま書く」
- 草稿 v3 の 4.6 および 5.4 第二限界「Phi 系列2モデルが測定不能である」

**いずれもモデルの性質ではなく、私のトークン抽出の誤りである。**
段E5 で Phi-3.5-mini が全族 0/13 だったのも同一原因である可能性が高い（未確認。確認する）。

### 修正

先頭トークンを「復号して文字が残る最初のトークン」に変更する。

```python
for form in (" " + w, w):
    for t in tok.encode(form, add_special_tokens=False):
        if tok.decode([t]).strip():
            return int(t)
```

他の8モデルは先頭トークンが語そのものであるため、この変更で ID は変わらない。
**Phi-3-medium のみ再測定が必要であり、実施する。**

## CC2. 実装欠陥 第11件：全体帰無 T の p 値が無効だった

追記83 CB7 で導入した全体帰無は、床族の引きから各目標の95パーセンタイル $q_{0.95,e}$ を取り、
$T = \#\{e : S_e > q_{0.95,e}\}$ の帰無分布を作るものだった。実装では
**閾値を取った引きと、$T$ を数える引きが同一**であった。

族最良は「床のうち最強の方向」に張り付くため、床族の最大値は**同値で重なる**。
その結果 $q_{0.95,e}$ が観測最大値と一致し、厳密不等号 $>$ では誰も超えられない。

**実測**：OLMo-2-13B・感情・F5 で `T_null_mean = 0.000`、評価で `0.100`。
帰無の $T$ の期待値は連続分布なら $13 \times 0.05 = 0.65$ であるべきところ、ほぼ 0 である。
したがって $p_T = P(T_{\mathrm{null}} \ge T_{\mathrm{obs}})$ は
**$T_{\mathrm{obs}} \ge 1$ でさえ有意になる、過度に緩い検定**になっていた。

### 撤回する記述

2026-10-07 に私が報告した

> 「感情軸だけが床を超え、評価軸は超えない」ではなく「両方とも超えるが、感情軸が圧倒的に強い」

は、**この無効な p 値に基づく。撤回する。** 評価次元が全体帰無を超えるかは、
修正した統計量で測り直すまで主張しない。

### 修正（本追記で固定する。結果を見る前に定義する）

床族の引きを $B = 4000$ 本生成し、**前半2000本で閾値と moment を定め、後半2000本で評価する**。

1. **計数**：$\mathrm{thr}_e = q_{0.95}(\text{前半}_e)$、$T_{\mathrm{obs}} = \#\{e: S_e > \mathrm{thr}_e\}$、
   $T_{\mathrm{null}}$ は後半から計算する。$p_T = (1 + \#\{T_{\mathrm{null}} \ge T_{\mathrm{obs}}\})/(1 + 2000)$
2. **連続統計量**：前半から $\mu_e, \sigma_e$ を取り
   $G = \sum_e (S_e - \mu_e)/\sigma_e$ とする。$G$ は連続であり同値の問題を持たない。
   $p_G = (1 + \#\{G_{\mathrm{null}} \ge G_{\mathrm{obs}}\})/(1 + 2000)$
3. **健全性**：床分布の異なり数の最小値と標準偏差の最小値を併記する

**主たる全体統計量は $G$ とする。** $T$ は読みやすさのために併記するが、同値の影響を受けうる
ことを明記する。

## CC3. 実装欠陥 第12件：生の測定値を保存していなかった

旧 `stageC3.py` は統計量の要約のみを JSON に書き、方向ごと・床ごとの測定値を保存していなかった。
そのため CC2 の修正に**GPU 測定のやり直しが必要になった**（約5時間）。

**修正**：測定と統計を分離する。

- `stageC3.py` は測定し、`raw_<tag>.npz`（族×読み出し×{標的 sel/test、F5、F4} の全配列）と
  `meta_<tag>.json` を保存する
- `c3stats.py` が npz から全統計量を計算する。**統計量の改訂に GPU を要しない**

**今後、測定スクリプトは生の測定値を必ず保存する。**
