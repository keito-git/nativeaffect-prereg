# 事前登録 追記21：Cliff's δ を100本の床からどう作るかを確定する

**対象**: 事前登録本体 §2 G1（「Cliff's δ ≥ +0.20」）
**作成**: 2026-09-27
**状態**: **G1 の判定統計量は1つも存在しない。GPU 障害で起動していない**
**由来**: 実験担当が実装中に、登録文が δ の集約方法を規定していないことを開示した

---

## U1. 規定漏れ

§2 G1 は「片側置換 p < 0.05（BH 補正後 q < 0.05）かつ **Cliff's δ ≥ +0.20**」と書いた。
**しかし δ が「軸 vs 100本の床」をどう対にするかを書いていない。** 少なくとも3通りある。

- **(a)** 刺激ごとに床100本の**平均**を取り、144対で対応のある δ
- **(b)** 軸144値と床 144×100 値を**プールして**対応のない δ
- **(c)** 床の引き1本ごとに δ を計算し、100個の δ の**中央値**

## U2. 決定：(a) を採る。既存慣行に合わせる

**`pos_ctrl_inplane.py:429` が in-plane 床でやっているのと同じ集約である。**

**理由**: α の件（追記18 R1）と fp16 の件（追記19 S2）と同型である。**C1・C2・C4 が (a) で計算されており、δ ≥ +0.20 という閾値は暗黙にこの慣行の上で決まっている。** 集約を変えれば閾値の意味が変わる。**測定間の比較可能性を優先する。**

**片側置換 p は登録どおり $(1+\#\{床 \ge 軸\})/101$。** p が 0 にならず、100本なら q<0.05 に到達できる（20本では不可能）。実験担当が自己検査で固定した。

## U3. ただし (a) は δ を膨らませる。必ず可視化する

**(a) は床100本を平均するので、比較対象の散らばりが $\sqrt{100}=10$ 分の1に縮む。**

**その結果、軸が床の平均をわずかに上回るだけで、刺激ごとの符号が揃い、δ が +1 に近づく。** (b) や (c) より**|δ| が大きく出る。すなわち「δ ≥ +0.20」という条件に対して非保守的である。**

**義務づけること**:

1. **δ が「床の平均に対する」ものであることを、結果の提示と同じ場所に書く。** 「軸が無作為な1本を上回る割合」ではない
2. **(c) の δ も併記する**（床の引き1本ごとに δ を計算し、100個の中央値と四分位）。**追加の GPU 計算は不要である。同じデータから計算できる**
3. **(a) と (c) が乖離した場合、乖離を報告する。** (a) だけで判定は行うが、**(c) が小さいセルは「床の平均は上回るが、個々の無作為方向に対する優越は限定的」と書く**

**3 を課す理由**: **G1 が通った場合、δ の大きさが「効果が大きい」根拠として引用される。** (a) の δ が構造的に大きく出ることを記録しておかなければ、誤読される。

**判定そのものは (a) で行う。** 結果を見てから (c) に切り替えることはしない。

## U4. 併せて確定：鏡映腕は極性1つ

**実験担当が、鏡映が $d$ の符号に不変であることを示した。**

$$x - 2(x\cdot(-d))(-d) = x - 2(x\cdot d)d$$

**したがって鏡映腕で ±両極性を測る必要はない。** 自己検査で固定済み。

- 加算腕: 144刺激 × 2極性
- **鏡映腕: 144刺激 × 1**

**これは費用の削減であって設計の変更ではない。** 測る対象は同じである。**前回の見積り60.76時間は鏡映も2極性として数えた誤りで、正しくは45.6時間。**

## U5. 記録：`script_sha256` はプロジェクトの既存標準だった

**既存の ICA 結果 JSON は `manifest.script` と `manifest.script_sha256` を記録している**（`rebuild_axes_nopad.py` / `e67608bf...`）。

**つまり G1 のヤコビアン段の出力にスクリプトのハッシュが無かったのは、新しい要件の追加ではなく既存標準からの後退だった。** ハッシュ食い違い事件（追記15・追記16）の原因がこれである。

**規則**: **新しいスクリプトを書くとき、同じ種類の既存出力が何を記録しているかを見る。** 既存標準を下回らないこと。
